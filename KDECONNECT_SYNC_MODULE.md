# KDE Connect Sync Module: Development Guide

## Why this doc

This guide describes how to add a robust sync module in Lucy for KDE Connect,
with one critical requirement:

- send files to a connected device into a specific target directory.


## Confirmed Constraints (important)

### 1) `kdeconnect-cli --share` does not accept a remote target directory

In `kdeconnect-cli` source, `--share` accepts only one value: `path or URL`.
No option exists like `--remote-dir`.

### 2) Share protocol packet also has no destination directory field

`kdeconnect.share.request` supports fields like `filename`, `text`, `url`,
`open`, etc., but no destination path.

### 3) On Android, share destination is app setting (global), not per send

In Android `ShareSettingsFragment`, destination folder is configured via
preferences (`share_destination_custom`, `share_destination_folder_uri`).
Default fallback is `Downloads`.

### 4) Exact path delivery requires SFTP mode

KDE Connect supports SFTP mount (`kdeconnect-cli --mount`,
`kdeconnect-cli --get-mount-point`). After mount, file copy to
`<mount_point>/<remote_path>` gives exact directory control.

## Module Scope

Name: `kdeconnect_sync` (new module)

Primary direction (MVP):

- local file changes -> remote device

Events to handle:

- `created`
- `modified`
- `moved`
- `deleted`

Current phase boundary:

- only change events for sending updates from PC to phone are in scope;
- `opened` intake flow (phone -> PC) is out of scope for this phase.


## Future Requirement (Deferred): Phone -> PC Intake on `opened`

Phone also runs Lucy and makes local commits.  
On a later phase, `opened` can intake phone-side committed changes as patch
packets (not by copying `.git` files).

Current status:

- deferred, not part of active implementation scope in this document version.

Required behavior:

1. Ensure phone is reachable and mounted (`kdeconnect-cli --mount`).
2. Resolve mounted path and locate phone repo patch queue directory.
3. Read pending patch packets from phone outgoing queue.
4. Apply packets locally with safe Git apply policy (`git am --3way` first).
5. If apply fails, keep packet + conflict snapshot and notify once.

Important:

- do not sync `.git` directory by raw file copy;
- use Git patch/merge operations as the source of truth.


## Ideal Strategy: Patch Queue + Lossless Git History

Goal:

- required files must appear on phone as fast as possible;
- no information loss on divergence;
- `kdeconnect_sync` and `git` modules stay separated.

### Critical Problem (must be handled explicitly)

Scenario:

1. user edits note on phone -> version `X` exists only on phone;
2. PC does not know about `X` yet;
3. user edits same note on PC -> version `Y`;
4. PC sync sends `Y` and may overwrite `X`.

This is not "parallel write race".  
This is "state divergence": sender writes from stale base state.

### Final Strategy (recommended)

Use two independent lanes in parallel:

1. Data plane (`kdeconnect_sync`, speed)
- reacts to `created/modified/moved/deleted`;
- enqueues sync task immediately;
- applies short "быстрое объединение частых изменений" window (150-300 ms);
- creates patch packets and writes them into project queue directory;
- transfers packet files to phone project queue directory via KDE Connect.

2. Control plane (`git`, truth)
- keeps current lossless conflict resolution policy (union/markers/explicit conflict commit);
- both devices commit quickly, so working trees are usually clean;
- performs local `add/commit/push` in background;
- never copies `.git` between devices.

### Patch Queue Contract

Project-local queue paths:

- PC -> phone:
  - PC outgoing: `<repo>/.lucy/patch_queue/outgoing_pc_to_phone`
  - phone incoming: `<repo>/.lucy/patch_queue/incoming_pc_to_phone`
  - phone ack: `<repo>/.lucy/patch_queue/ack_pc_to_phone`
- phone -> PC:
  - phone outgoing: `<repo>/.lucy/patch_queue/outgoing_phone_to_pc`
  - PC incoming: `<repo>/.lucy/patch_queue/incoming_phone_to_pc`
  - PC ack: `<repo>/.lucy/patch_queue/ack_phone_to_pc`
- conflict archive: `<repo>/.lucy/patch_queue/conflicts`

Per packet files:

- `<patch_id>.patch`: unified diff generated by Git (`git diff --binary` or `git format-patch --stdout` scope);
- `<patch_id>.json`: metadata with:
  - `patch_id`;
  - `path_list`;
  - `base_commit`;
  - `base_blob_by_path`;
  - `created_at`;
  - `author_device`.

Note:

- for PC `modified` flow, `path_list` must represent all file changes included
  in the produced commit (full dirty tree), not only the original event path.

Receiver-side Lucy consumes packets from its `incoming_*` directory in order
and writes one ack file per applied packet (`<patch_id>.ack`) to matching
`ack_*` directory.

### Safety Rule for Patch Apply

Phone never blindly overwrites target files.

Apply policy:

1. Validate path safety (inside repo, no `..`, no absolute paths).
2. Check idempotency: if `patch_id` already applied, skip and re-ack.
3. Validate base:
   - if current blob for every path equals expected `base_blob_by_path`, apply;
   - else try `git apply --3way --index` for safe merge.
4. If apply fails, do not overwrite target:
   - save incoming version and patch into `patch_queue/conflicts`;
   - mark conflict for later Git reconciliation.

### Git-Backed Sync State (no extra DB)

Do not keep a separate SQLite/JSON database outside Git.

Keep sync state inside repository Git object DB using a dedicated service ref
(for example `refs/lucy/kdeconnect-state`), where each tracked note path stores:

- `expected_remote_blob`;
- `expected_local_blob`;
- `last_sync_timestamp`.
- `last_outgoing_patch_id`;
- `last_incoming_patch_id`;
- packet status map (`queued`/`sent`/`applied`/`duplicate`/`superseded_by_git`/`conflict`/`busy`) by `patch_id`.

State updates are committed only after successful sync actions.

### Updated Sync Algorithm

Case A: `modified` on PC -> send to phone quickly (patch mode)

1. `kdeconnect_sync` receives event and enqueues file task.
2. It waits short coalesce window (150-300 ms); event paths are only a trigger.
3. `git` module stages and commits full current repo dirty state (`git add -A` scope).
4. `kdeconnect_sync` builds patch packet from committed delta.
5. It writes `<patch_id>.patch` and `<patch_id>.json` into
   `.lucy/patch_queue/outgoing_pc_to_phone`.
6. It transfers packet files to phone `.lucy/patch_queue/incoming_pc_to_phone`.
7. Phone Lucy applies packet with base-check + `--3way` fallback.
8. Phone Lucy writes `<patch_id>.ack`; PC marks packet delivered.
9. If no ack/failed apply, packet is retried; on repeated failure, keep packet
   and raise one root-cause notification.

Case B: `opened` on PC -> deferred

- out of scope in current phase;
- will be specified and implemented in a separate phase.

### Delivery Order Scenarios (must be order-safe)

Scenario 1: phone receives Git sync first, then patch packet

1. Phone already has `origin_commit` in history.
2. Incoming packet references the same `origin_commit`.
3. Receiver checks commit reachability (`merge-base --is-ancestor`).
4. If commit already present, packet is not applied.
5. Ack status becomes `superseded_by_git`.

Scenario 2: phone receives patch packet first, then Git sync

1. Packet is applied and recorded (`applied`).
2. Later Git sync brings canonical commit from peer.
3. Integration uses normal safe flow; do not force reapply of equivalent
   cherry-picks.
4. If equivalence is detected, duplicate changes are skipped.
5. If equivalence is not detected and conflict appears, keep current lossless
   conflict policy (preserve both sides).

### Conflict Policy

- `last-writer-wins` is forbidden;
- preserve both versions on divergence;
- if patch cannot be applied safely, archive patch and conflicting content;
- all conflict resolution remains lossless and is captured by Git history;
- Git remains authoritative for merge history and no-loss reconciliation.


## Git Module Changes Needed (minimal)

Prefer minimal edits in `git` and keep orchestration in `kdeconnect_sync`.

1. Keep `git` module responsible only for Git operations.
2. Add service entrypoints callable from `kdeconnect_sync`:
   - `commit_dirty_tree(...)` (global staging `git add -A` scope);
   - `build_patch_for_commit(...)`;
   - `apply_patch_packet(...)`;
   - `has_commit(...)`.
3. Keep global staging mode intentionally:
   - event paths only trigger processing;
   - commit should include all current repo dirty changes.
4. Add dedup checks before apply:
   - skip if `origin_commit` already reachable;
   - skip if `patch_id` already processed.
5. Add explicit apply result statuses:
   - `applied`;
   - `duplicate`;
   - `superseded_by_git`;
   - `conflict`;
   - `busy`.
6. Reuse one repo-level lock for all mutating commands:
   - `add`, `commit`, `am`, `apply`, `pull`, `push`.
7. Keep current lossless merge behavior as default reconciliation policy.

## Path Mapping Rules

Given:

## Transfer Flows

### A) `patch-queue` mode (default for text/note changes)

1. Ensure device is reachable.
2. Mount device and resolve mount point.
3. Build phone queue target:
   - `<mount_point>/<kdeconnect_remote_root>/.lucy/patch_queue/incoming_pc_to_phone/`
4. Build patch packet on PC:
   - create local commit from full current repo dirty state (`git add -A`);
   - generate `<patch_id>.patch` from commit;
   - generate `<patch_id>.json` metadata.
5. Copy packet files atomically into phone `incoming_pc_to_phone/`.
6. Phone Lucy applies packet:
   - validate metadata and paths;
   - apply with `git am --3way` (preferred) or `git apply --3way --index`;
   - on success, commit if needed and write `<patch_id>.ack` into `ack_pc_to_phone/`.
7. PC receives ack (read from phone `ack_pc_to_phone/`), marks packet delivered, and
   advances Git-backed sync state.

For `moved` and `deleted`:

- include rename/delete in patch payload from Git diff;
- do not run ad-hoc file delete on phone before patch apply.

### B) `sftp-copy` fallback mode (binary/unsupported cases)

Used only when patch mode is not applicable:

- binary file too large for patch policy;
- file type explicitly excluded from patch flow;
- emergency fallback after repeated patch apply failures.

Rules:

1. Run CAS-like safety check before overwrite.
2. Write atomically (`tmp -> fsync -> rename`).
3. If safety check fails, save conflict snapshot, do not overwrite.


## Error/Notification Policy (anti-spam)

Use single root-cause notifications per incident, with rare mode:

- `safe_notify(..., use_rare_mode=True)`
- key example: `kdeconnect-sync-network:<device_id>`

Do not send separate notifications for each failed sub-step (`mount`, `copy`,
`delete`) during the same outage. One consolidated root-cause notification is
enough.

Also:

- include operation summary in one message;
- include first actionable error only.


## State and Truthfulness

To avoid false "synced" status:

- persist per-file sync record in Git-backed sync state ref
  (`refs/lucy/kdeconnect-state` or equivalent);
- record both local and remote expected blob hashes plus last successful sync timestamp;
- record packet state (`queued`, `sent`, `acked`, `apply_failed`) by `patch_id`;
- update this ref only after successful ack/apply;
- if any step fails, do not advance sync state commit.

This prevents status lying about last successful remote sync.


## Execution Model

Keep shell calls isolated and inspectable:

- one command per subprocess call;
- capture exit code/stdout/stderr;
- apply timeout from config.

Minimum command set:

- `kdeconnect-cli --list-available --id-name-only`
- `kdeconnect-cli -d <id> --mount`
- `kdeconnect-cli -d <id> --get-mount-point`
- `git format-patch --stdout`
- `git am --3way` or `git apply --3way --index`

Environment requirement:

- user session D-Bus must be available;
- `kdeconnectd` must be running.

If D-Bus unavailable, report one root-cause notification and stop processing.


## Implementation Plan in Lucy

Architecture requirement:

- do not implement `kdeconnect_sync` as one large file;
- split implementation into multiple focused modules by responsibility;
- keep public module entrypoint thin, move heavy logic to internal helpers.

## Practical Answer: "How to send to exact device directory?"

Use mounted SFTP path, but transport patch files (default):

- mount device filesystem with KDE Connect;
- resolve mount point;
- copy patch packet files to
  `<mount_point>/<kdeconnect_remote_root>/.lucy/patch_queue/incoming_pc_to_phone/`;
- phone Lucy applies patch locally in its repo.

`--share` cannot set remote directory per transfer. It can only rely on the
receiver-side configured destination folder.
